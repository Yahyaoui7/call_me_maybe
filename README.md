# Call Me Maybe

## Description

Call Me Maybe is a Python project about **function calling with a small language model**.

The goal is to read natural language prompts and convert them into structured function calls.

For example, if the input prompt is:

```text
What is the sum of 2 and 3?
```

The program should not answer `5` directly. Instead, it should output a JSON object like this:

```json
{
    "prompt": "What is the sum of 2 and 3?",
    "name": "fn_add_numbers",
    "parameters": {
        "a": 2.0,
        "b": 3.0
    }
}
```

The main goal is to make the output **valid JSON** and match the function schema.

---

## Project Goal

This project teaches how to make a small LLM produce reliable structured output.

A normal LLM can generate invalid JSON or extra text. To avoid this, the project uses **constrained decoding**.

Constrained decoding means that at each generation step, the model can only choose from valid next tokens.

Instead of allowing the model to write anything, the program limits the possible output so the final result is easier to parse and validate.

---

## Features

* Read prompts from a JSON input file
* Read function definitions from a JSON file
* Validate input data with Pydantic models
* Use a small LLM model through the provided SDK
* Generate function call results

## Algorithm Explanation

The program follows these steps:

1. Parse command-line arguments.
2. Load the prompts JSON file.
3. Load the function definitions JSON file.
4. Validate the input files with Pydantic models.
5. Build a prompt for the LLM.
6. Ask the model to choose the best function and extract parameter values.
7. Use constrained decoding to reduce invalid output.
8. Build the final JSON result with Python.
9. Save all results to the output JSON file.

---

## Constrained Decoding Approach

A normal LLM chooses the next token from the whole vocabulary.

In constrained decoding, the program creates a set of `allowed_ids`.

These are token IDs that are valid for the current step.

Example:

If the program expects a JSON object to start, the only valid next token may be:

```text
{
```

So the allowed token set contains only the token ID for `{`.

Then the program checks the model logits and chooses the best token only from the allowed IDs.

Simplified logic:

```python
allowed_ids = get_allowed_ids(current_text)
next_id = choose_best_allowed_token(logits, allowed_ids)
```

This is safer than:

```python
next_id = choose_best_token(logits)
```

because `choose_best_token()` can choose any token, including invalid text.

The final JSON structure is built by Python when possible. This improves reliability because Python can always create valid JSON with `json.dump()`.

## Design Decisions

### Pydantic models

Pydantic is used to validate input data.

The project defines models such as:

* `PromptItem`
* `Parameter`
* `FunDef`

This helps catch invalid input early.

### Literal types

The parameter type is limited to:

```python
Literal["number", "string", "boolean", "integer"]
```

This prevents invalid types like `float`, `text`, or `array` when they are not supported.

### Python builds final JSON

The LLM should not be trusted to write the full final JSON freely.

The model helps choose the function and values, but Python creates the final object:

```python
{
    "prompt": prompt,
    "name": function_name,
    "parameters": parameters,
}
```

This makes the output more reliable.

### Clear error handling

The program should handle:

* missing files
* invalid JSON
* wrong input format
* validation errors
* model generation errors

Errors should be clear and should not crash the program unexpectedly.

The target is:

Because the final JSON is written by Python, the output file should stay parseable.

## Challenges Faced

### Invalid JSON generation

The model can generate extra text or broken JSON.

Solution: use constrained decoding and build final JSON with Python.

### Different model output shapes

The model logits or token IDs may come as lists, nested lists, tensors, or arrays.

Solution: normalize them with helper functions like `get_last_logits()` and `encode_to_ids()`.

### Wrong input files

The input JSON may be missing or malformed.

Solution: validate the files and raise clear errors.

### Function selection

Some prompts may be ambiguous.

Solution: compare the prompt with all function descriptions and choose the best valid function.
